# Planner Playbook

- Read `PRODUCT_VISION.md`, `.okf/README.md`, and the affected code/docs first.
- Define one user-visible outcome aligned with an existing goal.
- Use `.okf/templates/spec.md` for a feature and `.okf/templates/task.md` for
  bounded implementation work.
- Include scope boundaries, acceptance criteria, API/data effects, edge cases,
  open questions, dependencies, and verification.
- Do not turn an unresolved policy into a requirement. Label it as an open question.
- Keep React optional and backend behavior authoritative.
