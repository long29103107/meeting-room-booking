# Task Log — 001_001: Core Backend Room/Booking Contracts

- Date: 2026-10-26
- Status: Implementation complete; PostgreSQL integration verification pending.
- Vision alignment: `PRODUCT_VISION.md` API v1 contract, `EMPLOYEE`/`ADMIN`
  roles, owner/admin booking rules, and PostgreSQL overlap guarantee.

## Starting state

- Controllers contained most business logic and returned JPA entities directly.
- Backend routes used `/api`, role naming used `USER`, and the frontend/README
  used query names that differed from the versioned API contract in the Product
  Vision.
- The booking schema already contained a PostgreSQL exclusion constraint, but
  there were no backend tests.

## Changes

- Added `RoomService` and `BookingService`; controllers now delegate business
  behavior to services.
- Added room and booking request/response DTOs so HTTP responses do not serialize
  JPA entities directly.
- Reorganized backend packages into the conventional layer-first layout:
  `controller`, `service`, `repository`, `entity`, and `dto`; moved JPA entities
  into the dedicated `entity` package.
- Set local Spring datasource defaults to `jdbc:postgresql://localhost:5432/meetingroom`
  with `postgres` / `Password123`, while retaining environment-variable overrides
  for Docker and other environments.
- Aligned paths and parameters with Product Vision: `/api/v1`, `/bookings/me`,
  availability `startTime`/`endTime`, and calendar `from`/`to`.
- Renamed the demo employee authority to `EMPLOYEE`; kept `ADMIN` with employee
  access. Room mutations and the all-bookings endpoint remain ADMIN-only.
- Added consistent JSON error envelopes, including authentication and access
  denied responses. Constraint conflicts return 409 without exposing SQL details.
- Added Swagger UI at `/swagger-ui.html` and OpenAPI JSON at `/v3/api-docs`,
  with documented Basic Auth and operation descriptions. The docs are public;
  protected API routes still require the appropriate demo account.
- Kept sample room seeding in Flyway V1 and aligned JPA entity column lengths
  and nullability with that migration. Hibernate `ddl-auto=validate` checks the
  migrated schema at startup; demo users stay in-memory.
- Enforced future booking creation, active-room booking, future-only employee
  cancellation, owner/admin cancellation authorization, and room availability
  range/capacity validation.
- Added unit tests, HTTP security tests, and PostgreSQL Testcontainers tests for
  endpoint authorization, validation, overlap conflicts, and adjacent intervals.
- Updated the frontend API caller and README to match the documented route and
  role contract.
